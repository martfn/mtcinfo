Algoritmia

O que é um algoritmo?

Conjunto de expressões simbólicas que representam ações, testes de condições e estruturas de controlo, para especificar um problema e a sua solução.

O algoritmo não é a solução: é a forma de chegar à solução. Aprende-se construindo e testando; não se aprende a copiar, ler ou decorar.

5 características (Knuth)

  • Finitude – todos os passos têm fim previsto.
  • Definitude – sem ambiguidade em nenhuma instrução.
  • Entrada – identificar os dados de entrada (se existirem).
  • Saída – produz dados de saída.
  • Eficácia – passos simples o suficiente para serem entendidos/executados.

Passos para resolver um problema

1) Especificar o problema → 2) Definir estratégia/planificação (viabilidade, top-down vs bottom-up) → 3) Conceber o algoritmo → 4) Codificar (JavaScript, PHP, C, Java…) → 5) Testar e corrigir erros → 6) Documentar.

Top-down

  • Do geral para o específico; divide o problema em sub-problemas, sucessivamente.
  • Ignora detalhes no início; só se codifica quando a especificação está completa.
  • Comum na programação procedimental.

Bottom-up

  • Parte de blocos simples pré-existentes (ex.: objetos) e liga-os até chegar ao processo final.
  • Reutilização de blocos; prioriza programação e testes.
  • Comum na POO.
Três momentos de um algoritmo: 1. entrada de dados → 2. processamento → 3. saída de dados. (Ex.: lâmpada – entradas: lâmpada nova, escadote; operações: subir, retirar, colocar, descer.)

Programar e programa

Programar = “comunicar com o computador”: dar instruções, escritas numa linguagem de programação, para resolver problemas com lógica (identificar o problema, pensar a solução, escrever código, testar, corrigir, melhorar).

Programa = conjunto de instruções que o computador consegue executar (o que fazer e como fazer).

Variáveis e tipos de dados

Variável

  • Espaço em memória onde se guarda informação; tem um nome que a identifica.
  • O tipo de informação condiciona as operações possíveis.
  • O valor pode mudar durante o programa.
  • Dá um nível superior de abstração.

Nomes (regras)

  • Podem conter letras, números, _ e $; começam por letra, _ ou $.
  • Sem espaços, acentos ou especiais (@ # - ç ~ "); sem repetir nomes; sem palavras reservadas.
  • Case sensitive: mVariavel ≠ mvariavel.
  • Boas práticas: lower case ou camelCase, nomes com significado, prefixos, consistência.

Inválidos nos exemplos: Data Nascimento (espaço), concorrente#1pontuação (# e acento); NomeCompleto: NÚMERO é válido mas o tipo está errado.

JavaScript

Primitivos: boolean, number, string, null, undefined.

Complexos: array, function, object.

Memória

1 byte = 8 bits. O texto “Azul” ocupa 4 bytes (32 bits): cada letra é guardada como código (A=65, z=122, u=117, l=108) em binário.

No pseudocódigo as variáveis declaram-se no início (VAR nome:TIPO); podem usar-se tipos próprios, desde que claros e consistentes.

Estruturas de decisão

Alteram a execução sequencial. Todas as condições resultam num booleano (V/F), normalmente com operadores relacionais/lógicos.

Simples

SE cond ENTÃO
  comandos      // só se V
FIM SE

if (cond) { comandos; }

Composta

SE cond ENTÃO
  comandos1     // se V
SENÃO
  comandos2     // se F
FIM SE

if (cond) {…} else {…}

Encadeada

Pode aninhar-se qualquer número de decisões (um SENÃO com outro SE lá dentro). Em fluxograma: um losango por condição.

SE soma correta ENTÃO ESCREVE "parabéns"
SENÃO
  SE pontos > 5 ENTÃO ESCREVE "está quase"
  SENÃO ESCREVE "tenta outra vez"
  FIM SE
FIM SE
Chavetas em JS: sem { }, só a primeira instrução depende do if. Em if(t==30) alert("calor"); alert("t-shirt"); o 2.º alert corre sempre.

= vs == vs ===

  • = atribuição. if (t = 30) atribui 30 (e é sempre verdadeiro!).
  • == compara só o valor (ignora o tipo): 5 == "5" → true.
  • === compara tipo e valor: 5 === "5" → false.
  • Valores lidos de input/prompt são texto → valor === 30 é sempre false.

Decisão múltipla (ESCOLHA / switch)

  • Caso particular de SE…SENÃO encadeados: igualdade absoluta (valor e tipo) entre o seletor e as opções.
  • Não permite operadores relacionais/lógicos: CASO < 1000 é inválido.
  • Opção OUTRO / default é opcional.
ESCOLHA fruta                switch (n) {
  CASO "maça"  ESCREVE "2€"    case 1: console.log("Janeiro");
  CASO "kiwi"  ESCREVE "3,5€"           break;      // termina o case
  CASO OUTRO   ESCREVE "inválido"  case 2: …
FIM ESCOLHA                    default: console.log("inválido");
                             }

Sem break o código “cai” para o case seguinte. Isso permite agrupar casos: case "mb": case 1: pagm="Multibanco"; break;

Exercício: conversão de intervalos

Intervalos (“18 aos 25 anos”) não cabem num ESCOLHA: usa SE … E … encadeados, p. ex. idade ≥ 18 E idade ≤ 25.

Estruturas de repetição (ciclos)

Executam instruções várias vezes: algoritmos mais curtos e fáceis de manter. Dentro do ciclo só correm as instruções do ciclo.

REPETE ENQUANTO

REPETE ENQUANTO cond
  comandos
FIM REPETE

Testa a condição antes: pode executar 0 vezes.

FAZ … ENQUANTO

FAZ
  comandos
ENQUANTO cond

Testa depois: executa pelo menos 1 vez. No fluxograma, não há operações no caminho de volta.

REPETE … DE … ATÉ

REPETE c DE 1 ATÉ 9 PASSO 1
  comandos
FIM REPETE

Para nº de repetições conhecido.

Condicional = nº de repetições desconhecido · Contador = nº conhecido. Repete enquanto a condição for verdadeira; por isso o valor da condição tem de mudar dentro do ciclo, senão fica infinito (viola a finitude).

Funcionamento do ciclo com contador

1) inicializa o contador → 2) testa (contador ≤ valor final; com passo negativo, ≥) → 3) V: executa o bloco; F: termina → 4) altera o contador (+ passo) → 5) volta ao 2.

Exemplos

n = 1                      // contador manual
REPETE ENQUANTO n ≤ 9
  ESCREVE n
  n = n + 1
FIM REPETE

Ler até ser “zé”: FAZ … LÊ palavra … ENQUANTO palavra ≠ "zé". Total acumulado: total = total + valor dentro do ciclo, com total = 0 antes.

Qual o resultado? (PASSO)
  • n DE 1 ATÉ 9 PASSO 3 → 1, 4, 7
  • n DE 10 ATÉ 0 PASSO -1 → 10, 9, … , 0
  • n DE 1 ATÉ 9 PASSO -1 → nada (a condição é falsa logo à partida)

Ciclos aninhados: o ciclo interno executa por completo em cada iteração do externo.

7

Where’s the bug? Erros típicos

  • Resultado não guardado: num+10 não altera nada → num = num + 10.
  • Condição errada: SE idade = 60 (atribuição/igualdade exata) em vez de idade > 60 ou ==; atenção a > vs ≥.
  • Fluxograma sem ramo F: se a decisão não tiver saída falsa, falta tratar o outro caso.
  • Tipo do ESCOLHA: VAR num:NÚMERO mas CASO "1" (texto) → nunca coincide (igualdade absoluta). Falta ainda CASO OUTRO para valores inválidos.
  • Variável não inicializada: REPETE ENQUANTO n ≤ 9 sem n = 1; ou peso_total sem = 0.
  • Variável não declarada: usar peso sem VAR peso:NÚMERO.
  • Ciclo infinito: a condição nunca muda.
  • ESCOLHA com operadores: CASO < 1000.
  • SE vazio: SE c ENTÃO SENÃO … (ENTÃO sem comandos).
  • Ordem das condições: condições sobrepostas/encadeadas na ordem errada dão resultados errados.
Estratégia para analisar código: percorre-o linha a linha e regista o valor de cada variável a cada passo (tabela de memória).

JavaScript e DOM

O que é

  • Linguagem de programação para a Web; interpretada (não compilada); não é Java.
  • Nome oficial: ECMAScript. Começou no Netscape Navigator 2 (LiveScript, 1995).
  • Segura: não escreve ficheiros no cliente (exceto cookies/local storage). Mas o código-fonte é visível.

Linguagem weakly typed

  • Declaração não obrigatória; não se indica o tipo; o tipo muda e converte-se automaticamente.
  • Mais simples, mas mais propensa a erros.
  • Variável declarada sem valor = undefined; variável inexistente → ReferenceError.

Client-side

+ resposta rápida, alivia o servidor.

− depende do browser; código exposto.

Server-side

+ código protegido, acede a BD/ficheiros/API, sem dependência do cliente.

− mais carga no servidor; precisa de ligação.

Fluxo ao aceder a uma página

Browser faz pedido HTTP → servidor devolve o HTML → browser interpreta e constrói o DOM → renderiza → pede os restantes recursos (CSS, JS, imagens). O JS pode alterar o HTML a qualquer momento manipulando o DOM.

Onde pôr o JavaScript

Inline · embedded (<script>) · ficheiro externo (<script src="x.js">). O externo dá reutilização, manutenção e cache.

DOM (tree model)

Representação hierárquica do HTML com 3 tipos de nós: elemento (html, body, p…), atributo (title="…") e texto.

document.getElementById("id")       // devolve null se não existir; case-sensitive
el.title = "texto"                   // atributo
el.innerHTML = "<i>olá</i>"         // conteúdo (lê e escreve HTML)
el.style.backgroundColor = "red"     // estilo: camelCase
el.style.fontSize = "10pt"           // precisa de unidade ("10" não funciona)
input.value                          // valor de um campo (sempre texto)

Entrada e saída

alert(x)                        // mostra janela
idade = prompt("Idade?", 18)    // texto; Cancel → null
ok = confirm("Sair?")           // OK → true · Cancel → false
console.log("z =", z)           // consola (debug)

Conversão de tipos

+ soma números mas concatena se houver texto. parseInt(), parseFloat(), String() convertem explicitamente; isNaN(v) → true se não for número.

document.getElementById("pontos").value + 20 com valor 100 dá "10020" → usa parseInt(...).

Quanto dá? (conversão implícita)
  • 12 + 34 → 46 · "12" + "34" → "1234" · "A idade: " + 21 → "A idade: 21"
  • 1 + 4 + "cafés" → "5cafés" · "cafés" + 1 + 4 → "cafés14"
  • "2" * "4" → 8 · "resultado" + 1 + 2*4 → "resultado18" · "2"+"2"-"2" → 20
parseInt e isNaN
  • Ignora espaços à esquerda; lê até ao 1.º carácter não numérico; se o 1.º não for número → NaN.
  • parseInt("10.33"), ("10,78"), ("10 de Janeiro") → 10 · ("34 56 78") → 34 · (" 60 ") → 60 · ("Janeiro 10") → NaN
  • isNaN("123") → false · isNaN("Hello") → true · isNaN("2005/12/12") → true · isNaN(2005/12/12) → false

typeof e números aleatórios

typeof v → "boolean", "string", "number", "object", "function", "undefined" (arrays e null dão "object").

Math.random() → decimal em [0, 1[. Math.random()*4 → [0, 4[. Inteiro entre min e max: Math.floor(Math.random()*(max-min+1)+min). Probabilidade de 25%: Math.random() < 0.25.

Eventos

  • Ocorrem por ações do utilizador (rato, teclado, formulário, browser) ou automaticamente (timers).
  • Inline (onclick="…") a evitar; preferir el.onclick = function(){…}.
  • onkeydown: ao premir, repete continuamente · onkeyup: ao libertar, 1 vez · onkeypress: descontinuado.
  • Tecla premida: event.key (keyCode está descontinuado).
Ordem de execução: o browser lê o HTML de cima para baixo. Um <script> no <head> que usa getElementById corre antes do elemento existir → null. Soluções: script no fim do body, ou window.onload = function(){ … }.

Áudio e vídeo (HTML5)

Tags <audio>/<video> com <source> (nem todos os formatos funcionam em todos os browsers; o Safari não suporta Ogg). Áudio via JS:

var som = new Audio();  som.src = "ficheiro.mp3";
som.play();  som.pause();

Sintaxe: instruções terminam em ;. Comentários: // linha e /* bloco */.

Subalgoritmos (funções) e scope

Porquê?

Repetir código aumenta o tamanho e complica a manutenção. Subalgoritmos permitem reutilizar código, reduzir linhas, simplificar alterações e minimizar erros. Sem eles: programação linear; com eles: estruturada/modular (problema dividido em módulos reutilizáveis).

Tipos

  • Procedimento: executa instruções.
  • Função: executa e retorna um valor.
  • Intrínsecos: nativos (prompt, isNaN, Math.random, parseInt).
  • Extrínsecos: criados pelo programador.

Caixa preta

Invoca-se pelo nome (único), passam-se parâmetros, o subalgoritmo executa e devolve o resultado. Quem invoca não precisa de saber como funciona por dentro.

Sintaxe

function nome(p1, p2 = 33) {   // declaração; p2 tem valor por omissão
  // código
  return valor;                // opcional; TERMINA a função
}
var r = nome("Manel");         // invocação; sem return → undefined
  • Parâmetro não passado = undefined (ou o valor por omissão).
  • Código depois de um return nunca executa.
  • Callback: função passada a outra / chamada quando ocorre um evento (ex.: window.onload = function(){…}).
  • Parâmetros são cópias: alterar x++ dentro da função não muda a variável de fora.

Scope (visibilidade)

  • Global: declarada fora de funções; existe em todo o script até a página fechar. Atribuir sem var dentro de uma função cria uma global.
  • Local: declarada dentro da função; só existe nela e desaparece quando termina. Funções diferentes podem ter locais com o mesmo nome.
  • Regra da proximidade: procura primeiro no contexto atual e depois nos contextos acima, até ao global. Um parâmetro/local com o mesmo nome “esconde” a global.
  • Funções declaradas dentro de outra são locais a ela.
  • O mesmo vale para let.
Exemplos (qual o resultado?)
  • var nome="zé"; function f(){console.log(nome)} → f() mostra “zé” (usa a global).
  • function f(){var nome="zé"} f(); console.log(nome) → ReferenceError (local).
  • function f(){nome="zé"} f(); console.log(nome) → “zé” (sem var = global).
  • function sq(n){total=n*n} com var total=50; sq(20) → 400; com var total=n*n dentro → 50.
  • function inc(a,b){a++;b++} com a=4, b=8 → dentro 5 9; fora continua 4 8.
  • function f1(){ function f2(){…} }; chamar f2() fora de f1 → erro (f2 é local a f1).

Hoisting

As declarações var são “elevadas” para o topo do scope, mas sem o valor.

minha_var = 5; var minha_var;   console.log(minha_var)  // 5
console.log(x); var x = 5;      // undefined (não dá erro)
var a = 5, b; console.log(a + b) // NaN (5 + undefined)

Testa-te

Responde de cabeça antes de abrir cada pergunta.

Quais as 5 características de um algoritmo (Knuth)?

Finitude, definitude, entrada, saída e eficácia.

Top-down vs bottom-up?

Top-down parte do problema geral e divide-o em sub-problemas até ao detalhe (o código só começa no fim). Bottom-up parte de blocos simples pré-existentes e liga-os até ao processo final, reutilizando blocos.

REPETE ENQUANTO vs FAZ … ENQUANTO?

O primeiro testa a condição antes e pode não executar nenhuma vez; o segundo executa primeiro e testa depois, por isso corre pelo menos uma vez.

Quando usar ciclo condicional e quando ciclo com contador?

Condicional quando o nº de repetições é desconhecido; contador quando é conhecido à partida.

Porque pode um ciclo ficar infinito?

Porque o valor lógico da condição nunca muda dentro do ciclo (ex.: esquecer n = n + 1). Viola a finitude.

Porque é inválido CASO < 1000 num ESCOLHA?

O ESCOLHA só faz igualdade absoluta (valor e tipo) com o seletor; não aceita operadores relacionais nem lógicos. Para intervalos usa SE … E … encadeados.

Diferença entre =, == e ===?

= atribui; == compara só o valor (5 == "5" é true); === compara tipo e valor (5 === "5" é false).

Resultado de 1 + 4 + "cafés" e de "cafés" + 1 + 4?

“5cafés” e “cafés14”. Avalia-se da esquerda para a direita e o + só concatena a partir do momento em que aparece texto.

Porque é que campo.value + 20 dá “10020”?

O valor lido de um campo (ou de um prompt) é sempre texto, por isso o + concatena. Converte antes com parseInt() ou parseFloat().

Porque devolve getElementById null num script no head?

O browser lê o HTML de cima para baixo: o script corre antes de o elemento existir. Põe o script no fim do body ou usa window.onload.

O que acontece se usares fora da função uma variável declarada com var lá dentro?

Dá ReferenceError: a variável é local e desaparece quando a função termina. Sem var seria global.

Procedimento vs função; intrínseco vs extrínseco?

Procedimento executa instruções; função executa e retorna um valor. Intrínsecos são nativos da linguagem (prompt, isNaN, Math.random); extrínsecos são criados pelo programador.
