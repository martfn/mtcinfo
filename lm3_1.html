01 Cheatsheet Absoluta & Variáveis (T3-T4)

A fundação de qualquer algoritmo. O programa só processa informação se esta for armazenada na memória através de variáveis. Cada variável obriga a uma declaração de tipo.

Tipos de Dados e Sintaxe

A declaração tem de ser feita obrigatoriamente a seguir ao INÍCIO.

VAR nome : NÚMEROGuarda inteiros ou decimais. Permite contas (+, -, *, /).
VAR nome : TEXTOGuarda strings/caracteres (ex: "Maria", "Sim").
VAR nome : LÓGICOGuarda apenas VERDADEIRO ou FALSO.
VAR nome : DATAGuarda datas (menos comum no papel).
INÍCIO / FIMMarcadores delimitadores do programa global.

Comandos I/O e Operadores

LÊ variavelPausa o programa e guarda a introdução do utilizador na memória.
ESCREVE "txt"Imprime para o ecrã texto ou variáveis (ex: ESCREVE "Olá " + nome).
=Atribuição. Ex: soma = 2 + 2 (A variável soma passa a valer 4).
==, ≠, >, <, ≥, ≤Relacionais. Usados em avaliações de condições (retornam Lógico).
E, OU, NÃOLógicos. Juntam várias condições. O "E" exige que ambas sejam verdadeiras.

💡 Detalhe Importante: Operadores Relacionais vs Atribuição

Um erro clássico é confundir = (Atribuição, ex: A = 5, significa "guarda o valor 5 na variável A") com == (Comparação, ex: SE A == 5 ENTÃO, significa "Verifica se A é igual a 5"). No pseudocódigo de LabMM3, a avaliação da ficha é rigorosa nestes símbolos.

02 Simbologia Oficial de Fluxogramas (T1-T2)

A linguagem visual padrão. O fluxo lê-se sempre de cima para baixo e da esquerda para a direita. O uso da forma errada desconta cotação direta.

Terminais (Oval / Elipse)
Abre e fecha a execução do algoritmo. Só sai uma seta do INÍCIO e só entra uma seta no FIM.

Input / Output (Paralelogramo)
Sempre que o algoritmo comunica com o exterior. Pedir dados ao utilizador ou mostrar resultados.

Processamento (Retângulo)
Operações internas. Fórmulas matemáticas, atribuições de variáveis ou reinicializações.

Decisão (Losango)
Tem de ter uma expressão lógica no interior. Obrigatório: As setas de saída têm de estar marcadas com V e F.

03 Decisões Complexas: SE vs ESCOLHA (T4-T5)

A base da inteligência do algoritmo. Como obrigar o programa a tomar rotas diferentes consoante os dados processados.

1. O Ramo Condicional: SE-ENTÃO-SENÃO

Aceita todo o tipo de lógica relacional (maior, menor, igual). Se o teste avaliar para VERDADEIRO, executa o bloco ENTÃO. Se for FALSO, salta para o bloco SENÃO.

Exemplo ExplicativoDecisão Composta
SE (media ≥ 10) E (faltas ≤ 3) ENTÃO // Ambas as condições têm de ser cumpridas graças ao "E" ESCREVE "Aprovação Direta" SENÃO // Se a média for 9, ou as faltas forem 4, entra aqui. SE (media ≥ 8) ENTÃO // Isto é um "SE" aninhado (um SE dentro de um SENÃO) ESCREVE "Recurso" SENÃO ESCREVE "Reprovado" FIM SE FIM SE

2. A Decisão Múltipla Exata: ESCOLHA-CASO

A usar apenas quando queres testar uma única variável contra uma lista de valores estritos. Pensa nisto como um "Menu" de opções.

🚨 Erro Fatal de Exame

No comando ESCOLHA, não podes colocar variáveis ou operadores nos CASOS. O código CASO > 10 ou CASO var_limite dará cotação ZERO. Os casos têm de ser estáticos: CASO 1, CASO "A".

A Estrutura Correta do ESCOLHADecisão Múltipla
VAR dia : NÚMERO ESCREVE "Indique o dia da semana (1-7):" LÊ dia ESCOLHA dia CASO 1 ESCREVE "Domingo" CASO 2 ESCREVE "Segunda-feira" // ... saltando para poupar espaço CASO OUTRO // O "CASO OUTRO" captura qualquer input que não seja 1, 2, etc. (ex: se user digitar 9) ESCREVE "Dia inválido." FIM ESCOLHA

04 A Arte dos Ciclos (T6-T7)

A automatização do código. O algoritmo repete blocos até que a condição seja saciada (ENQUANTO) ou o limite do contador seja atingido (REPETE).

ENQUANTO (While)

A condição é verificada antes de entrar. Ideal para validações de Input, porque se a condição for inicialmente falsa, o ciclo nunca é executado.

Ciclo de Validação
VAR senha : TEXTO = "" // Enquanto a senha for errada, não avança. ENQUANTO senha ≠ "1234" FAZ ESCREVE "Introduza password:" LÊ senha // Variável de teste atualizada! FIM ENQUANTO ESCREVE "Acesso Permitido"

REPETE (For)

Usado quando o número de iterações é predeterminado. A anatomia do ciclo trata da variável contadora automaticamente (inicialização e incremento).

Anatomia: REPETE (var) DE (inicio) ATÉ (fim) PASSO (inc)
VAR soma : NÚMERO = 0 // Vai correr exatamente 5 vezes (i vale 1, 2, 3, 4, 5) REPETE i DE 1 ATÉ 5 PASSO 1 ESCREVE "Valor de i é: " + i soma = soma + i FIM REPETE

⚠️ O Perigo do Ciclo Infinito

Se, num fluxograma em papel (Ex. 7 Revisões), tiveres um Losango que atira uma seta para cima de volta ao fluxo, e não houver nenhum Retângulo (Processo) a alterar a variável desse losango, o programa cracha infinitamente. No papel, isso vale perda de cotação drástica.

05 Teste de Mesa e Estado de Memória (T8)

A técnica para "correr o código na cabeça". Consiste em criar uma matriz onde controlamos o estado de cada variável no tempo.

Código do Teste:

1. INÍCIO 2. VAR x: NÚMERO = 0 3. VAR y: NÚMERO = 10 4. ENQUANTO x < 2 FAZ 5. y = y - 2 6. x = x + 1 7. FIM ENQUANTO 8. y = y * x 9. FIM

A tua Folha de Resposta:

Iteração / PassoMemória [x]Memória [y]
Setup (Linhas 2, 3)010
1º Loop (x=0 < 2)1 (L6)8 (L5: 10-2)
2º Loop (x=1 < 2)2 (L6)6 (L5: 8-2)
Fim Loop (x=2. Sai)------
Linha 8 (y = 6 * 2)212

* No teste real, não precisas de escrever a coluna "Iteração". Basta fazeres a tabela com X e Y e ires riscando os valores anteriores à medida que calculas os novos.

06 Exercícios Práticos Resolvidos (Masterclass)

Abaixo encontras a resolução detalhada de exercícios tipificados das fichas práticas, com as armadilhas explicadas.

Problema A: Verificação de Par ou Ímpar (Ficha 3, Ex 3) Operador Módulo + SE

Desafio: Desenvolva um algoritmo que leia um número e informe se este é par ou ímpar.

INÍCIO // 1. Declaração obrigatória da variável de entrada VAR num : NÚMERO ESCREVE "Introduza um número inteiro:" LÊ num // 2. O truque: Usar MOD (Módulo / Resto da Divisão) // Se o resto da divisão por 2 for zero, o número é par. SE (num MOD 2 == 0) ENTÃO ESCREVE "O número introduzido é PAR." SENÃO ESCREVE "O número introduzido é ÍMPAR." FIM SE FIM
Problema B: Acumuladores e Filtros M/F (Ficha 6, Ex 13) Ciclo REPETE + Contadores

Desafio: Leia 10 pessoas (Sexo M/F) e apresente o total de estudantes do sexo feminino e masculino.

INÍCIO // 1. Definir as variáveis acumuladoras/contadoras (iniciadas a Zero!) VAR sexo : TEXTO VAR conta_M : NÚMERO = 0 VAR conta_F : NÚMERO = 0 // 2. Ciclo indexado pois sabemos exatamente que são 10 inputs REPETE i DE 1 ATÉ 10 PASSO 1 ESCREVE "Insira o sexo do aluno " + i + " (M ou F):" LÊ sexo // 3. Processamento de contagem (Atenção ao texto entre aspas) SE (sexo == "M") ENTÃO conta_M = conta_M + 1 SENÃO SE (sexo == "F") ENTÃO conta_F = conta_F + 1 SENÃO ESCREVE "Erro de Input. Assumido não catalogado." FIM SE FIM SE FIM REPETE // 4. Output Final (FORA do ciclo, para não repetir a mensagem 10 vezes) ESCREVE "Total Sexo Masculino: " + conta_M ESCREVE "Total Sexo Feminino: " + conta_F FIM
Problema C: Validação Contínua (Ficha 5, Ex 9 adaptado) Ciclo ENQUANTO

Desafio: Peça ao utilizador números sucessivos. O programa soma-os. Se o valor for menor que 10, termina o ciclo e imprime a soma final.

INÍCIO // 1. Iniciar variáveis. A variável de teste deve forçar a entrada no ciclo. VAR numero : NÚMERO = 10 VAR soma_total : NÚMERO = 0 // 2. Condição de paragem. Só roda enquanto o número for >= 10 ENQUANTO numero ≥ 10 FAZ ESCREVE "Insira um número (menor que 10 para terminar):" LÊ numero // Só somamos se o utilizador não colocou a chave de saída. SE (numero ≥ 10) ENTÃO soma_total = soma_total + numero FIM SE FIM ENQUANTO ESCREVE "Ciclo Terminado. A soma dos valores válidos é: " + soma_total FIM
